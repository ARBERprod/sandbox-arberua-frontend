# eSputnik: звіт для маркетингу


### Автоматичні воронки (event-driven)

Спрацьовують миттєво при відповідній дії користувача:

| Воронка | Тригер | Event key | Що відбувається |
|---------|--------|-----------|-----------------|
| Реєстрація | Користувач зареєструвався | — | Контакт підписується (subscribe), додається у групу `registered` |
| Підтвердження email | Користувач підтвердив email | `email_confirmed` | Контакт оновлюється, відправляється event |
| Скидання пароля | Натиснув "Забув пароль" | `password_reset_requested` | Відправляється event |
| Підтвердження замовлення | Замовлення оформлене | `order_confirmed` | Контакт додається у групу `customers`, відправляється event з деталями замовлення |
| Нарахування бонусів | Бонуси нараховані | `bonus_accrued` | Відправляється event |

### Scheduled воронки (cron)

Виконуються автоматично за розкладом:

| Воронка | Event key | Розклад | Логіка |
|---------|-----------|---------|--------|
| Покинутий чекаут | `checkout_abandoned` | Щогодини | Корзини з товарами без замовлення > 30 хв |
| Зниження ціни в кошику | `cart_price_drop` | Щодня 10:00 | Поточна ціна товару < ціна при додаванні |
| Зниження ціни у вішлісті | `wishlist_price_drop` | Щодня 10:00 | Поточна ціна < ціна при додаванні у вішліст |
| Бонуси на день народження | `birthday_bonus_accrued` | Щодня 09:00 | Сьогодні день народження користувача |
| Бонуси згорають | `bonus_expiring_soon` | Щодня 10:00 | Бонуси згорають протягом 7 днів |
| Синхронізація контактів | — | Неділя 03:00 | Масовий експорт всіх контактів (до 3000/запит) |

## Що потрібно від маркетингу

### 1. Підтвердити назви груп контактів

Переконайтесь, що в eSputnik створені ці групи (або повідомте правильні назви):

| Група | Коли додається контакт |
|-------|------------------------|
| `registered` | При реєстрації на сайті |
| `email_confirmed` | Після підтвердження email |
| `customers` | Після оформлення замовлення |

### 2. Підтвердити назви подій (event keys)

Створіть відповідні сценарії (workflows) в eSputnik для кожного event key:

| Event key | Воронка |
|-----------|---------|
| `email_confirmed` | Підтвердження email |
| `password_reset_requested` | Скидання пароля |
| `order_confirmed` | Підтвердження замовлення |
| `checkout_abandoned` | Покинутий чекаут |
| `cart_price_drop` | Зниження ціни в кошику |
| `wishlist_price_drop` | Зниження ціни у вішлісті |
| `bonus_accrued` | Нарахування бонусів |
| `birthday_bonus_accrued` | Бонуси на день народження |
| `bonus_expiring_soon` | Бонуси згорають |

### 3. Передати ID кастомних полів (якщо потрібні додаткові)

Наразі бекенд передає стандартні поля: `phone`, `birthday`. Якщо потрібні додаткові кастомні поля — створіть їх в адмінці eSputnik і передайте ID розробникам.

## Дані для побудови email-шаблонів в eSputnik

Нижче — параметри (params), які передаються в кожному event. Використовуйте їх як velocity-змінні при створенні шаблонів листів.

### Event `order_confirmed`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email покупця | `"user@email.com"` |
| `OrderId` | UUID замовлення | `"abc-123-def"` |
| `OrderNumber` | Номер замовлення | `"1001"` |
| `OrderDate` | Дата замовлення (ISO) | `"2026-03-07T12:00:00Z"` |
| `TotalAmount` | Сума замовлення | `"5000"` |
| `Currency` | Валюта | `"UAH"` |
| `Items` | JSON масив товарів | див. нижче |

**Структура товару в `Items`:**

```json
{
  "sku": "product-uuid",
  "name": "Сорочка Classic Fit",
  "qty": "2",
  "price": "1500"
}
```

### Event `checkout_abandoned`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `FirstName` | Ім'я | `"Олександр"` |

### Event `password_reset_requested`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |

### Event `cart_price_drop`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `ProductId` | UUID товару | `"product-uuid"` |
| `OldPrice` | Стара ціна (в кошику) | `"1500"` |
| `NewPrice` | Нова (поточна) ціна | `"1200"` |

### Event `wishlist_price_drop`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `ProductId` | UUID товару | `"product-uuid"` |
| `OldPrice` | Ціна при додаванні | `"4500"` |
| `NewPrice` | Нова (поточна) ціна | `"3600"` |

### Event `bonus_accrued`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `BonusAmount` | Кількість нарахованих бонусів | `"100"` |
| `Reason` | Причина нарахування | `"purchase"` |

### Event `birthday_bonus_accrued`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `FirstName` | Ім'я | `"Олександр"` |

### Event `bonus_expiring_soon`

| Параметр | Опис | Приклад |
|----------|------|---------|
| `EmailAddress` | Email користувача | `"user@email.com"` |
| `BonusAmount` | Кількість бонусів, що згорають | `"500"` |
| `ExpiresAt` | Дата згорання | `"2026-03-14T00:00:00Z"` |

## Автоматичні події при Subscribe

При використанні методу Subscribe contact (реєстрація) eSputnik автоматично створює системні події:

| Подія | Коли виникає |
|-------|-------------|
| `subscribeFromApi-registration` | Створено **новий** контакт через subscribe |
| `subscribeUpdateFromApi-registration` | Оновлено **існуючий** контакт через subscribe |

Маркетологам потрібно прив'язати **welcome-сценарій** саме до події `subscribeFromApi-registration` (або до `email_confirmed`, якщо welcome-лист має відправлятись після підтвердження email).
